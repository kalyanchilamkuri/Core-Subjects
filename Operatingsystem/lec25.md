# Deadlock Detection & Recovery and Memory Management Foundations

---

## Part 1: Deadlock Detection

If an operating system does not employ Deadlock Prevention or Deadlock Avoidance, deadlocks can occur. The system must provide:
1. An algorithm to periodically inspect system state to **detect if a deadlock has occurred**.
2. A recovery scheme to **break the deadlock and restore execution**.

---

### A. Single Instance of Each Resource Type: The Wait-For Graph (WFG)

When every resource type has exactly one instance, we simplify the Resource Allocation Graph into a **Wait-For Graph (WFG)** by collapsing all resource nodes:

```
Resource Allocation Graph:                Wait-For Graph (WFG):
( P1 ) ──► [ R1 ] ──► ( P2 )              ( P1 ) ──────► ( P2 )
  ▲                     │                   ▲              │
  │                     │       ===>        │              │
[ R2 ] ◄────────────── ( P2 )               └──────────────┘
                                            (Cycle Detected = Deadlock!)
```

* **Construction**:
  * An edge from process $P_i \to P_j$ exists in the Wait-For Graph if and only if $P_i$ is waiting for a resource currently held by $P_j$.
* **Detection Rule**:
  * **A deadlock exists in the system if and only if the Wait-For Graph contains a directed cycle!**
  * Algorithms like **Depth-First Search (DFS)** detect cycles in $O(V + E)$ or $O(n^2)$ time where $n$ is the number of processes.

---

### B. Multiple Instances per Resource Type

When resource types have multiple instances, a simple cycle does not guarantee deadlock. We run a variant of the **Banker's Algorithm Safety Check**:
* Uses vectors `Available[m]`, `Allocation[n][m]`, and `Request[n][m]` (the current outstanding requests).
* Any process whose requests cannot be satisfied by currently available plus released resources is permanently flagged as **Deadlocked**.

---

## Part 2: Deadlock Recovery

Once a deadlock is detected, the OS must break the circular wait using one of two approaches:

### 1. Process Termination
* **Option A: Abort All Deadlocked Processes**:
  * Breaks the deadlock immediately, but is extremely expensive because completed computations and partial results are discarded.
* **Option B: Abort One Process at a Time**:
  * Abort one deadlocked process, release its resources, and re-run the detection algorithm. Repeat until the cycle is broken.
  * *Victim Selection Criteria*: Which process to kill first?
    1. Process priority (kill lower priority first).
    2. Execution time (kill process that just started, sparing one that has run for hours).
    3. Resources held (kill process holding the most locked resources).
    4. Whether the process is interactive or a background batch job.

### 2. Resource Preemption
Preempt resources from some processes and allocate them to others until the deadlock cycle breaks:
1. **Selecting a Victim**: Determine which resource to preempt from which process to minimize rollback costs.
2. **Rollback**: The victim process cannot continue normally because its required resource was taken away. The OS must roll back the victim to a safe **checkpoint** (or restart it entirely).
3. **Starvation Prevention**: If victim selection is purely cost-based, the same poor low-priority process might always be chosen as the victim, starving forever.  
   * *Solution*: Include a timestamp or "number of times rolled back" counter in the cost metric.

## Part 3: Memory Management Foundations

The primary goal of memory management is to keep multiple processes in RAM simultaneously to **maximize CPU utilization**.

```
Logical Address (Generated by CPU) ──► [ MMU Hardware ] ──► Physical Address (Actual RAM)
```

---

### 1. Logical Address vs. Physical Address

| Concept | Logical (Virtual) Address | Physical Address |
|---|---|---|
| **Definition** | Address generated by the CPU while executing instructions. | The actual physical storage location on the physical RAM hardware chip. |
| **Visibility** | User programs see and use only logical addresses. | Never directly accessible by user-space applications. |
| **Generation** | Generated by CPU hardware and compiler. | Computed at runtime by the **Memory Management Unit (MMU)**. |
| **Address Space** | Contiguous range from $0$ to $\text{Max}$. | Physical RAM addresses ($0$ to physical memory size). |

---

### 2. The Memory Management Unit (MMU)

The **MMU** is a specialized hardware component located on the CPU chip that performs **runtime hardware translation** of logical addresses into physical addresses:

```
        CPU
         │ (Logical Address: 346)
         ▼
+-----------------+
|       MMU       |
|  Base Register  | ──► [ Base = 14000 ]
|     (Relocation)|
+-----------------+
         │
         │ Physical Address = 14000 + 346 = 14346
         ▼
+-----------------+
|   Physical RAM  | ──► Location 14346 Accessed!
+-----------------+
```

### Relocation Register (Base Register) and Limit Register:
* **Base (Relocation) Register**: Holds the smallest physical address allocated to the process in RAM.
* **Limit Register**: Specifies the exact size of the process's allocated address space.
* **Hardware Protection Check**:
  $$\text{If } (\text{Logical Address} < \text{Limit Register}) \implies \text{Physical Address} = \text{Base Register} + \text{Logical Address}$$
  $$\text{Else } \implies \text{Raise Trap (Segmentation Fault / Memory Access Violation!)}$$

---

### 3. Memory Fragmentation

```
Internal Fragmentation                       External Fragmentation
+-----------------------------------+        +-----------------------------------+
| Frame Size: 4 KB                  |        | Process P1 (2 MB)                 |
| [ Process Data: 1 KB ]            |        +-----------------------------------+
| [ Unused Space: 3 KB (Wasted!) ]  |        | Free Hole: 1 MB (Too small for P3)|
+-----------------------------------+        +-----------------------------------+
Unused memory inside an allocated block!     | Process P2 (3 MB)                 |
                                             +-----------------------------------+
                                             | Free Hole: 1 MB (Too small for P3)|
                                             +-----------------------------------+
                                             Total free memory = 2 MB, but split!
                                             Cannot allocate P3 (2 MB)!
```

### A. Internal Fragmentation
* Occurs when memory is allocated in fixed-size blocks (like pages or fixed partitions).
* If a process requests 1 KB and the system allocates a 4 KB block, the remaining 3 KB inside the block goes unused.
* **Key characteristic**: Wasted space resides **inside** an allocated partition.

### B. External Fragmentation
* Occurs in dynamic contiguous allocation when variable-sized blocks of free memory are scattered across RAM.
* Although total free memory across the system is sufficient to satisfy a process's request, the memory is non-contiguous, so the process cannot be loaded.
* **Solutions**:
  1. **Compaction** (expensive memory shuffling).
  2. **Non-Contiguous Allocation (Paging & Segmentation)**: Completely eliminates external fragmentation by allowing a process to reside in non-contiguous frames across physical RAM!
